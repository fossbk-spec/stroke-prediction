# Methods

> Draft v0.1 (2026-10-14). Reporting follows TRIPOD+AI [@Collins2024TRIPODAI] where applicable. Items marked **[TBD]** depend on the experiment run, which has not been executed yet.

## 2.1 Study design

This is a methodological re-analysis study. We do not propose a new stroke-risk model. We quantify how much commonly used but leaky evaluation protocols inflate the apparent performance of stroke-prediction models trained on a widely used public dataset. The design has two parts:
1. an evidence synthesis that characterises the evaluation practices of published studies (Section 2.2);
2. a controlled experiment in which the same models, hyperparameters and folds are evaluated under one leak-free protocol and several leaky protocols (Sections 2.3–2.7).

Data leakage is any use of information during model development that would not be available when the model is applied to new patients [@Kaufman2012Leakage; @Kapoor2023Leakage].

## 2.2 Evidence synthesis

We ran a rapid review (not a systematic review) [@Garritty2021RapidReview], reported following PRISMA 2020 conventions [@Page2021PRISMA], with four human decision gates.
- **Sources:** Europe PMC (499 records), OpenAlex (300 records) and Semantic Scholar (297 records), plus 3 seed papers, searched on 2026-10-13 for 2020–2026.
- **Eligibility:** journal articles that predict incident stroke from tabular clinical or EHR data with at least one machine-learning model and report recall/sensitivity, AUC or F1.
- **Screening:** after two-stage de-duplication (DOI/PMID and fuzzy title matching), 981 unique records were screened and 74 were eligible.
- **Data extraction:** 19 core studies were extracted into an eight-field evidence matrix with verbatim quotations and source locations.
- **Integrity checks:**
  - every DOI was verified against Crossref;
  - retracted articles and articles with an expression of concern were excluded;
  - all numbers cited from the literature were checked by an automated reverse audit against the evidence matrix.

The search strings, screening decisions, PRISMA counts and evidence matrix are released with the code.

## 2.3 Data sources

**Primary dataset.** The Kaggle Stroke Prediction Dataset: 5,110 records, one row per patient identifier, and 249 stroke events (4.87%). It has ten predictors:
- demographics: age, gender, ever married, work type, residence type;
- clinical: hypertension, heart disease, average glucose level, body-mass index;
- smoking status.

Body-mass index is missing for 201 records. "Unknown" smoking status is kept as its own category, because missingness patterns can carry predictive information [@Sperrin2020Missing].

**Provenance check and patient-disjoint sample.** Matching on patient identifier showed that all 5,110 records of the primary dataset are contained in the larger Kaggle Cerebral Stroke Prediction-Imbalanced dataset (43,400 records, 783 events, 1.80%), with identical predictor values and outcome labels. The larger file stores missing smoking status as empty values; we recoded these as "Unknown" to match the primary dataset. Removing the 5,110 overlapping patients left a patient-disjoint sample of 38,290 records with 534 events (1.39%). This sample comes from the same source, so we use it only as a robustness check, not as external validation. The counts are reported in a provenance file generated by a released script.

Both datasets are publicly available, de-identified Kaggle datasets. **[TBD: licence statement and ethics waiver wording.]**

## 2.4 Models and preprocessing

We evaluated logistic regression, random forest [@Breiman2001RF] and gradient boosting [@Friedman2001GB], with the same hyperparameters in every protocol:
- **Logistic regression:** liblinear solver, at most 2,000 iterations.
- **Random forest:** 400 trees, minimum 3 samples per leaf.
- **Gradient boosting:** 200 trees, learning rate 0.05, maximum depth 3.

Preprocessing:
- Continuous predictors (age, glucose, body-mass index) were imputed with a distance-weighted k-nearest-neighbour imputer (k = 5) [@Troyanskaya2001KNN]. All imputation is part of the fitted pipeline, so the same procedure applies at development and at deployment [@Sperrin2020Missing]. They were standardised for logistic regression only.
- Binary predictors were imputed with the most frequent value.
- Ever-married was coded 0/1.
- Nominal predictors were one-hot encoded.

Class imbalance was handled with SMOTENC [@Chawla2002SMOTE], the SMOTE variant for mixed categorical and continuous features. It was applied to the imputed raw predictors, before one-hot encoding, so that synthetic records keep valid categories. The number of neighbours was capped at the minority-class size minus one.

## 2.5 Evaluation protocols

All protocols use the same raw data, models and hyperparameters, and repeated 5-fold cross-validation (5 repeats; repeat *r* uses random seed 42 + *r*). SMOTENC uses `sampling_strategy="auto"`, which balances the data it is applied to at 1:1. The protocols were finalised after an independent methods review of an earlier design. In that design, the oversampling protocol scored resampled rows and the preprocessing-leakage protocol changed the order of operations. Both confounded the contrast with P0. The design choices below follow the methodological literature cited in each row.

| Protocol | Procedure | Mechanism isolated | Comparison with P0 |
|---|---|---|---|
| P0 Correct | Folds split by patient (stratified group k-fold). On each training fold: impute, apply SMOTENC, then encode/scale. Scored on the untouched validation fold | None (reference) | Reference |
| P1a SMOTE before split, as published | Imputation and SMOTENC on the entire dataset, then ordinary stratified k-fold on the resampled rows; validation folds include synthetic records | Reproduction of the published flaw [@Dritsas2022Stacking; @Rehman2023RDET; @Santos2018CVImbalanced; @Vandewiele2021Oversampling] | Unmatched (different evaluation population and prevalence): descriptive only |
| P1b SMOTE before split, matched | Global imputation and SMOTENC as in P1a. Each P0 training fold receives its original rows plus all synthetic rows; scored on the same original validation patients as P0 | Synthetic records derived from validation patients entering training | Matched |
| P2 Preprocessing before split | P0 order and row types. Validation records are added only to the data used to fit the imputer and the encoder/scaler; SMOTENC still sees training rows only | Leakage of preprocessing statistics only [@Rosenblatt2024Leakage] | Matched |
| P3 Balanced evaluation set | P0 predictions scored on all validation positives plus an equal number of randomly selected negatives | Evaluation prevalence (reporting artefact) [@Saito2015PR] | Matched (validation subset) |
| P4 No resampling | The P0 pipeline without the resampling step | Effect of 1:1 resampling itself [@Carriero2025Imbalance; @Piccininni2024Resampling; @Andersen2026TippingBalance] | Matched |

Patient-grouped (subject-wise) splitting mirrors the intended use on new patients, whereas record-wise splitting can greatly overestimate accuracy [@Saeb2017SubjectWise]. P0, P1b, P2, P3 and P4 share identical patient-grouped folds within a repeat. For P1b we record the number of synthetic training records. We also record how many of them have a validation patient as their nearest original minority neighbour in the encoded feature space; this is an approximate attribution of their SMOTENC parent, not the generator's true lineage.

P3 does not reproduce the cited workflows of Yang et al. or Vu et al. literally [@Yang2021Hypertensive; @Vu2024Suita], since those studies sampled before splitting. It is a controlled experiment on evaluation prevalence. Recall is identical to P0 by construction, while precision, PR-AUC, accuracy and Brier score shift with prevalence. P4 removes the resampling step from the same pipeline, so the scaler is fitted on the original training rows. Its estimand is therefore "the same pipeline without resampling", not a single-factor change.

## 2.6 Performance measures

For each validation fold we computed:
- threshold-free measures: area under the ROC curve (ROC-AUC) and average precision (PR-AUC);
- the Brier score [@Brier1950; @VanCalster2019Calibration];
- at a fixed decision threshold of 0.5, the default used by most of the reviewed studies: accuracy, recall, precision, specificity and F2.

The Brier score is prevalence-sensitive, so we do not interpret its change under P3 as a change in calibration.

We also recorded the numbers of validation records, positive records and synthetic records.

## 2.7 Statistical analysis

- **Single protocols.** We report the mean of the repeat means and, descriptively, the minimum and maximum repeat means. We do not report a *t*-interval, because cross-validated estimates share patients across folds and repeats and standard intervals under-cover [@Bates2023CV].
- **Inflation.** For the matched protocols (P1b, P2, P3, P4), inflation is the difference from P0 computed at the fold level, for the same model, repeat and fold.
- **Missing values.** A fold pair is excluded if either value is missing (for example ROC-AUC on a single-class fold). The numbers of valid folds and repeats are reported.
- **Intervals for differences.** A naive paired *t*-test on resampled splits has an inflated type I error [@Dietterich1998Tests]. We therefore report the mean difference with a 95% interval from the corrected resampled *t* method [@Nadeau2003Inference; @Bouckaert2004Corrected]: variance factor 1/*J* + mean(*n*<sub>test</sub>/*n*<sub>train</sub>) and *J* − 1 degrees of freedom, where *J* is the number of valid fold pairs. The method assumes exchangeable paired fold differences. We treat these intervals as a sensitivity analysis, not as population-performance intervals.
- **P1a** receives no paired difference.

## 2.8 Software and reproducibility

Reporting follows TRIPOD+AI [@Collins2024TRIPODAI] and the REFORMS checklist for ML-based science [@Kapoor2024REFORMS]. The analysis code is open source and covered by unit tests. The tests use instrumented fit functions to check that:
- no validation record reaches any fit under P0;
- validation records enter only the preprocessing fits under P2 and never the resampling step;
- P1b scores the same validation patients as P0;
- P3 reuses the P0 probabilities;
- P4 never resamples.

It runs in Python with scikit-learn and imbalanced-learn **[TBD: exact versions of the final run]**. The primary analysis is reproduced with:

`python -m src.leakage_experiment --output reports/leakage`

The robustness analysis needs the source file and a preparation step: `python scripts/prepare_cerebral_disjoint.py`, followed by the experiment with `--data data/raw/cerebral-stroke-disjoint.csv`. A `--benchmark` option times one fold per model and protocol before the full run.
