## 2.1 Study design

This is a methodological re-analysis study. We do not propose a new stroke-risk model. We quantify how much commonly used but leaky evaluation protocols inflate the apparent performance of stroke-prediction models trained on a widely used public dataset. The design has two parts:
1. an evidence synthesis that characterises the evaluation practices of published studies (Section 2.2);
2. a controlled experiment in which the same models, hyperparameters and folds are evaluated under one leak-free protocol and several leaky protocols (Sections 2.3–2.7).

Data leakage is any use of information during model development that would not be available when the model is applied to new patients [@Kaufman2012Leakage; @Kapoor2023Leakage].

## 2.2 Evidence synthesis

We ran a rapid review (not a systematic review) following PRISMA 2020 conventions, with four human decision gates.
- **Sources:** Europe PMC (499 records), OpenAlex (300 records) and Semantic Scholar (297 records), plus 3 seed papers, searched on 2026-10-13 for 2020–2026.
- **Eligibility:** journal articles that predict incident stroke from tabular clinical or EHR data with at least one machine-learning model and report recall/sensitivity, AUC or F1.
- **Screening:** after two-stage de-duplication (DOI/PMID and fuzzy title matching), 981 unique records were screened and 74 were eligible.
- **Data extraction:** 19 core studies were extracted into an eight-field evidence matrix with verbatim quotations and source locations.
- **Integrity checks:**
  - every DOI was verified against Crossref;
  - retracted articles and articles with an expression of concern were excluded;
  - all numbers cited from the literature were checked by an automated reverse audit against the evidence matrix.

The search strings, screening decisions, PRISMA counts and evidence matrix are released with the code.

## 2.3 Data sources

**Primary dataset.** The Kaggle Stroke Prediction Dataset: 5,110 records, one row per patient identifier, and 249 stroke events (4.87%). It has ten predictors:
- demographics: age, gender, ever married, work type, residence type;
- clinical: hypertension, heart disease, average glucose level, body-mass index;
- smoking status.

Body-mass index is missing for 201 records. "Unknown" smoking status is kept as its own category.

**Provenance check and patient-disjoint sample.** Matching on patient identifier showed that all 5,110 records of the primary dataset are contained in the larger Kaggle Cerebral Stroke Prediction-Imbalanced dataset (43,400 records, 783 events, 1.80%), with identical predictor values and outcome labels. The larger file stores missing smoking status as empty values; we recoded these as "Unknown" to match the primary dataset. Removing the 5,110 overlapping patients left a patient-disjoint sample of 38,290 records with 534 events (1.39%). This sample comes from the same source, so we use it only as a robustness check, not as external validation. The counts are reported in a provenance file generated by a released script.

Both datasets are publicly available, de-identified Kaggle datasets. **[TBD: licence statement and ethics waiver wording.]**

## 2.4 Models and preprocessing

We evaluated logistic regression, random forest and gradient boosting, with the same hyperparameters in every protocol:
- **Logistic regression:** liblinear solver, at most 2,000 iterations.
- **Random forest:** 400 trees, minimum 3 samples per leaf.
- **Gradient boosting:** 200 trees, learning rate 0.05, maximum depth 3.

Preprocessing:
- Continuous predictors (age, glucose, body-mass index) were imputed with a distance-weighted k-nearest-neighbour imputer (k = 5). They were standardised for logistic regression only.
- Binary predictors were imputed with the most frequent value.
- Ever-married was coded 0/1.
- Nominal predictors were one-hot encoded.

Class imbalance was handled with SMOTENC [@Chawla2002SMOTE], the SMOTE variant for mixed categorical and continuous features. It was applied to the imputed raw predictors, before one-hot encoding, so that synthetic records keep valid categories. The number of neighbours was capped at the minority-class size minus one.

## 2.5 Evaluation protocols

All protocols use the same raw data, models and hyperparameters, and repeated 5-fold cross-validation (5 repeats; repeat *r* uses random seed 42 + *r*).

| Protocol | Procedure | Leakage mechanism | Representative published practice |
|---|---|---|---|
| P0 Correct | Folds split by patient (stratified group k-fold); imputation, encoding, scaling and SMOTENC fitted on the training fold only; scored on the untouched validation fold | None | — |
| P1 SMOTE before split | Imputation and encoding fitted, and SMOTENC applied, on the entire dataset; then ordinary stratified k-fold on the resampled data | Synthetic neighbours of validation cases enter training, and validation folds contain synthetic records | Oversampling before cross-validation or before the train–test split [@Dritsas2022Stacking; @Rehman2023RDET] |
| P2 Preprocess before split | Imputation and encoding fitted on all records; SMOTENC applied to the training fold only; real validation records | Imputer and scaler statistics include validation records | Preprocessing fitted before splitting |
| P3 Balanced test | Trained as P0; each validation fold randomly down-sampled to 1:1 before scoring | Evaluation prevalence differs from the target population | Artificially balanced evaluation sets [@Yang2021Hypertensive; @Vu2024Suita] |
| P4 No resampling | As P0 without SMOTENC | None (reference for the effect of resampling) | — |

Under P0, P2, P3 and P4 the folds are identical within a repeat. P3 reuses the P0 predictions, so its difference from P0 isolates the effect of the evaluation set.

## 2.6 Performance measures

For each validation fold we computed:
- threshold-free measures: area under the ROC curve (ROC-AUC), average precision (PR-AUC), and Brier score as a measure of calibration [@VanCalster2019Calibration];
- at a fixed decision threshold of 0.5, the default used by most of the reviewed studies: accuracy, recall, precision, specificity and F2.

We also recorded the number of validation records, positive records and synthetic records.

## 2.7 Statistical analysis

- Fold results were first averaged within each repeat, so that the repeat is the unit of analysis.
- For each protocol, model and measure we report the mean across repeats with a 95% *t*-interval.
- Inflation is the paired difference from P0 for the same model and repeat, with a 95% *t*-interval.
- We interpret the magnitude and direction of the paired differences rather than declaring significance from overlapping folds.

## 2.8 Software and reproducibility

The analysis code is open source and covered by unit tests, including tests that synthetic records appear only in P1 validation folds and that no patient appears in both training and validation folds under P0. It runs in Python with scikit-learn and imbalanced-learn **[TBD: exact versions of the final run]**. One command reproduces all results:
